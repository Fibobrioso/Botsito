# docs/validation/
Un FUNCTIONALITY VALIDATION REPORT por rama (`F##-nombre.md`, formato en `_template.md`), los
informes de fidelidad y ventaja (desde F26) y `PREREGISTRO.md` (umbrales, commiteado antes de abrir
cualquier holdout). El estado del informe (`WAITING_FOR_USER_VALIDATION`) no se edita tras el
merge: la validacion queda registrada en PROJECT_STATE (Completed Features, Change Log) y en el tag
`stable/F##`. Una auditoria global tiene su propio informe `AUDITORIA-<fecha>-<tema>.md`.
